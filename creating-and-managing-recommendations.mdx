Recommendations are the actionable findings raised as part of a survey. Each recommendation captures what was found, the risk it presents, what action should be taken, and who is responsible.

Recommendations are created from the **Recommendations** tab on a survey record. They also roll up to the site record and client record so engineers and clients can track them across the portfolio.

To view, update, or respond to an existing recommendation, see [The recommendation record](/the-recommendation-record).

## Adding a recommendation

From the survey's **Recommendations** tab, click **+ Add Recommendation**.

### Recommendation details

| Field | Notes |
|-------|-------|
| Recommendation Name | A short title describing the finding |
| Recommendation ID | Auto-generated reference number (e.g. 2026.01) |
| Status | Current status of the recommendation. Defaults to **New** |
| Date Issued | Date the recommendation was raised. Defaults to today |
| Survey Reference | Pre-filled with the current survey |
| Due Date | Target date for completion |

### Area details

| Field | Notes |
|-------|-------|
| Building / Structure | The specific building or structure where the finding was made |
| Area Coordinates | Location reference within the site |

### Risk classification

Select the **Risk Classification** category from the dropdown, and then the **Sub Classification** within it. This links the recommendation to the risk element it relates to (for example, *Protection → Manual fire fighting measures / hose reels + hydrants*).

### Recommendation type

Select the type of improvement the recommendation calls for:

| Type | Use when |
|------|----------|
| **CapEx** | Completing the recommendation requires capital expenditure — for example, building something or installing a physical protection system |
| **Human Element** | The recommendation is about processes or management practices — better risk management on site by staff |

### Risk level

The **Risk Level** is determined using a **5×5 risk matrix**. Select the cell that best represents the combination of consequence and probability.

**Consequences (columns A–E):**

| Code | Level |
|------|-------|
| A | Not Significant |
| B | Minor |
| C | Moderate |
| D | Major |
| E | Severe |

**Probability (rows 1–5):**

| Code | Level |
|------|-------|
| 1 | Impractical |
| 2 | Not Likely |
| 3 | Possible |
| 4 | Likely |
| 5 | Certain |

The matrix is colour-coded green (low), amber (medium), and red (high). Selecting a cell auto-calculates the **Calculated Risk** score.

### Risk priority

| Field | Notes |
|-------|-------|
| Priority | The urgency of the recommendation: Critical (P1), Significant (P2), or Advisory (P3) |
| Client Classification | Internal classification label for the client-facing report |

| Priority | Meaning |
|----------|---------|
| **Critical (P1)** | Imminent deficiencies that need immediate attention — for example, physical inadequacies that significantly expose the site or company to higher risk, or deficiencies in processes and practices that are readily rectified |
| **Significant (P2)** | Procedural or physical deficiencies that need attention once plans are in place to address Priority 1 items |
| **Advisory (P3)** | Procedural or physical deficiencies that need attention once plans are in place to address Priority 1 and 2 items |

### Finding description

A rich-text field for describing what was observed during the survey. Supports formatting, images, and embedded content.

### Recommendation

A rich-text field for the recommended corrective action. This text appears in the issued report.

### Loss estimates

An expandable section for estimating the financial impact of the recommendation:

| Field | Description |
|-------|-------------|
| Cost to Complete | The estimated cost of implementing the recommendation |
| Before Completion | The estimated loss if the recommendation is **not** implemented |
| After Completion | The estimated loss once the recommendation has been implemented |

For each value, you can enter a single estimate, a range, or both.

### Recommendation contact

Assign a client contact to this recommendation. The contact is responsible for implementation and receives an email notification whenever an engineer posts a response on the recommendation. See [Responses](/the-recommendation-record#responses).

## Recommendation statuses

Recommendations are tracked through to completion, with their status updated at each review. A recommendation can have one of the following statuses:

- New
- In Progress
- Under Review
- No Progress
- Pending Verification
- Completed
- Declined
- Superseded
- Withdrawn

New recommendations default to **New**.

## The recommendations list

Recommendations are listed in a filterable table — on the main **Recs** page, and on the **Recommendations** tab of client, site, and survey records.

| Column | Description |
|--------|-------------|
| Reference | Auto-generated ID |
| Risk Level | The calculated risk score from the matrix |
| Recommendation | Short summary of the recommendation |
| Priority | Critical (P1), Significant (P2), or Advisory (P3) |
| Loss Est. | Estimated loss value |
| Status | Current recommendation status |

### Filtering recommendations

Every recommendations table in TruRisk — the main **Recs** page and the Recommendations tab on client, site, and survey records — has the same set of filters. Filters that don't apply in context are hidden (for example, the **Client** filter isn't shown on a client record).

| Filter | Description |
|--------|-------------|
| Search | Find recommendations by keyword |
| Year | The year the recommendation was raised |
| Country | The country of the client or site |
| Risk Level | Pick a single cell on the risk matrix to show recommendations with that risk level (see below) |
| Survey Type | The type of survey the recommendation was raised in |
| Classification | The recommendation's risk classification, selected from the classification tree |
| Priority | Critical (P1), Significant (P2), or Advisory (P3) |
| Client | The client the recommendation belongs to |
| Status | The recommendation's current status |
| Overdue | Toggle on to show only overdue recommendations |

#### Filtering by risk level

The **Risk Level** filter opens the risk matrix. Each cell combines a consequence rating (columns) with a probability rating (rows). Click a single cell to filter by that risk level — the selected level is shown as the **Calculated Risk**. Click **Clear** to remove the filter.

<img src="/images/guide/risk-level-matrix.png" alt="The Risk Level filter showing the 5×5 risk matrix" />

| Consequences | Probability |
|--------------|-------------|
| A – Not Significant | 1 – Impractical |
| B – Minor | 2 – Not Likely |
| C – Moderate | 3 – Possible |
| D – Major | 4 – Likely |
| E – Severe | 5 – Certain |

#### Overdue recommendations

A recommendation is overdue when its due date has passed and it is still open. Declined, Withdrawn, and Superseded recommendations are never counted as overdue.

Overdue recommendations are highlighted in the table with a red **due [time] ago** label under their status. Turn on the **Overdue** toggle to show only these recommendations.

The summary cards at the top of the tab show an aggregate breakdown of recommendations by **Status**, **Priority**, and **Estimated Loss Before Completion**.

<Tip>
  Loss estimate values are shown in your preferred currency. See [Currency preference](/currency).
</Tip>

## Exporting recommendations

You can export recommendations in three ways:

| From | How |
|------|-----|
| **A single recommendation** | Open the recommendation and click **Export**, then choose **Microsoft Word (.docx)** or **Comma-separated values (.csv)**. |
| **A recommendations table** | Tick the checkboxes next to the recommendations you want (or the checkbox in the header to select all), then click **Export** in the bar above the table. |
| **A site** | On the site record, open the **`···`** menu and select **Export Recommendations** to export all of that site's recommendations. |

<Tip>
  Apply filters before selecting recommendations in a table — for example, filter to **Overdue** or a single **Priority** — to export just the set you need.
</Tip>
