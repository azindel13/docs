---
title: "Bulk importing sites"
description: "How to import multiple sites at once into an existing client record."
---

The bulk site import lets you add multiple sites to an existing client at once by uploading a spreadsheet. All imported sites will be created under the client record you start the import from.

To start an import, open the client record, go to the **Sites** tab, click the **···** menu, and select **Import Sites for this Client**.

<Info>
  If you need to create both clients and sites at the same time, use the [bulk client import](/bulk-importing-clients) from the Clients page instead. That flow accepts one file and creates client and site records together.
</Info>

## Step 1: Upload file

Drag and drop your file into the upload area, or click **Browse** to select it from your computer.

Accepted formats: `.xlsx`, `.csv`

The file should contain one row per site. Company-level fields are not required, since all sites will be linked to the current client.

## Step 2: Map fields

TruRisk automatically attempts to match your file's column headers to the corresponding site fields. The mapping screen shows three columns:

| Column | Description |
| --- | --- |
| TruRisk Field | The field name in TruRisk |
| Headers | The matched column from your file (or a dropdown to select one manually) |
| Preview data | Sample values from the first rows of your file |

For each field you want to import, click the **✓** (tick) button to confirm the mapping. Only confirmed mappings are imported — any field left unconfirmed is ignored, even if it was auto-matched.

Required fields (marked with **\***) must be confirmed before you can proceed:

| Field | Description |
| --- | --- |
| Site Name\* | The name of each site |
| Site Country\* | The country where the site is located |

The remaining fields are optional — confirm any that you want to include in the import.

<Tip>
  If a column in your file doesn't auto-match, use the **Header** dropdown for that field to select the correct column manually.
</Tip>

## Step 3: Preview import

Review the sites that will be created before committing. This step shows a summary of the records TruRisk has parsed from your file, along with any warnings about rows that couldn't be matched or mapped.

## Step 4: Review results

After the import runs, a results screen shows which sites were created successfully and which (if any) failed, along with the reason for each failure.

To fix errors, correct the relevant rows in your file and re-run the import. Only sites that were not successfully imported previously will be created — sites that already exist under this client are ignored, so re-importing won't create duplicates.

<Info>
  The import only **creates** new sites. It does not update existing site records. If a site with the same name already exists under this client, that row will be skipped.
</Info>

## Supported fields

| Field | Description and format |
| --- | --- |
| Site Name\* | Required. The name of the site, e.g. the facility or location name. Site names should be unique within a client, as a row whose site name already exists under that client is skipped. |
| Site Country\* | Required. The country where the site is located. Use the full country name (e.g. `Germany`). |
| Site Description | A short free-text summary of the site, e.g. what it is used for and its main activities. |
| Site Currency | The site's local currency, entered as a three-letter ISO 4217 code (e.g. `GBP`, `USD`, `EUR`). This is the currency the site's values are recorded in. |
| Site SIC Code | The US Standard Industrial Classification (SIC) code for the activity carried out at this site, which may differ from the company's main activity. Use the four-digit US SIC code only (e.g. `2511`), without the description. Some codes start with a zero (e.g. `0111`), so format the column as text so the leading zero isn't dropped. The SIC code drives the site's occupancy in TruRisk. |
| Site State / Province | The state, province, county or region the site is in (e.g. `Texas`, `Ontario`, `Bavaria`). |
| Site GPS Coordinates | The site location as a latitude/longitude pair in decimal degrees, latitude first, separated by a comma (e.g. `51.5074, -0.1278`). Use a minus sign for south latitudes and west longitudes rather than N/S/E/W letters, and don't use degrees-minutes-seconds. Accurate coordinates matter for mapping and catastrophe exposure, so take them from the site itself rather than the postcode centre where possible. |
| Site Total Insured Value | The site's total insured value (TIV), in the site currency. Enter a plain number with no currency symbols or thousands separators (e.g. `12500000`). |
