Each recommendation has its own record, where you can see all of its details, track its status, and exchange updates with the client. Open a recommendation by clicking it in any recommendations table — on the **Recs** page, or on the Recommendations tab of a client, site, or survey record.

## Header

The header shows the recommendation's name, its reference (for example, **2026.01**), and its priority. The following actions are available:

- **Export** — download the recommendation as **Microsoft Word (.docx)** or **Comma-separated values (.csv)**
- **Edit Recommendation** — update any of the recommendation's details. See [Recommendations](/recommendations) for a description of each field.
- **`···`** menu — **Export** or **Delete** the recommendation

## Key dates and status

The top of the record shows:

| Field | Description |
|-------|-------------|
| Date Issued | When the recommendation was raised |
| Due Date | The target date for completion |
| Status | The recommendation's current status. Click it to change the status directly from the record. See [Recommendation statuses](/recommendations#recommendation-statuses). |
| Last Updated | When the recommendation was last changed |

## Observations & Issues and Recommendation

The main panel shows the **Observations & Issues** (what was found during the survey) and the **Recommendation** (the action the client should take).

## Responses

**Responses** is where engineers and clients communicate about the recommendation — for example, progress updates, feedback on status changes, or end-of-year assessments.

- Engineers post responses from the engineer portal. When an engineer posts a response, the **contact** assigned to the recommendation receives an email notification.
- Clients post responses from their Client Portal. When a client posts a response, the assigned engineer is notified.

All responses from both sides appear together in this section, so the full history of the recommendation is in one place.

## Contact

The client contact responsible for the recommendation. Click **Add Contact** to assign one.

<Info>
  Assign a contact to every recommendation you share with a client — otherwise no one on the client's side is notified when you post a response.
</Info>

## Risk Classifications

| Field | Description |
|-------|-------------|
| Risk Classification | The risk element the recommendation relates to |
| Sub Classification | The more specific area within that risk element |
| Risk Category | The risk level from the risk matrix (for example, **B4**) |
| Client Classification | The client-facing classification label |
| Recommendation Type | **CapEx** (requires capital expenditure) or **Human Element** (process or management practice) |

## Area Details

Where the recommendation applies — the **Building/Structure** and **Coordinates** — and the **Survey**, **Site**, and **Client** it belongs to, each linking to its record.

## Loss Estimates

| Field | Description |
|-------|-------------|
| Cost to Complete | The estimated cost of implementing the recommendation |
| Before Completion | The estimated loss if the recommendation is not implemented |
| After Completion | The estimated loss once the recommendation has been implemented |

Each value can be a single estimate, a range, or both.
